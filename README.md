# 屏蔽大肥鱼-折叠

屏蔽 B站评论区里「大肥鱼」这类 AI 人格账号的油猴脚本，被清掉的评论可以折叠查看。

> 本项目基于 [ybyz2/bilibili-dafeiyu-blocker](https://github.com/ybyz2/bilibili-dafeiyu-blocker) 的 **1.3.0** 版修改，沿用它 MIT 许可证。
> 原版只在评论区顶部报一句「已清 N 条」，这里把它做成了可以展开翻查的记录清单，另外补上楼中楼查看和一轮性能优化。详见 [相比原版 1.3.0 的改动](#相比原版-130-的改动)。

## 它做了什么

大肥鱼是一类在 B站评论区批量刷屏的 AI 人格账号，特征很好认：昵称带「鱼」或「鲸」、正文里塞 `@`、爱用 `——` 和 `「」`、动不动自称「本鲸」`主人`。

脚本在**接口数据返回的那一刻**就把命中的评论摘掉，所以页面从头到尾不会闪一下。同时它不直接销毁这些数据，而是收进「已清记录」里，想看的时候展开就行。

## 功能

- **四档屏蔽强度**：小杯 / 标准 / 杀戮 / 只屏蔽 @，按误伤程度自己挑
- **三种楼中楼策略**：只删楼中楼 / 整楼删除 / 不管楼中楼
- **已清记录折叠面板**：评论区顶部显示 `已清 N 条`，点开可翻看被删评论的原文、作者和命中原因，鼠标移到头像上能看用户资料、一键进主页
- **无闪烁**：拦截 `fetch` / `XHR` 响应，评论从未进入页面
- **跟随 B站夜间模式**
- **置顶评论始终保留**
- 兼容篡改猴 / 脚本猫 / 暴力猴，只依赖 `GM_getValue` / `GM_setValue`，没装管理器时自动退回 `localStorage`

右键脚本管理器图标 → 管理扩展程序 → 打开「允许运行用户脚本」（没有这一项就打开「开发者模式」）→ 重启浏览器。

装好自动生效，页面上不会多出按钮。

## 使用

点浏览器工具栏的脚本管理器图标 → **屏蔽大肥鱼** → **设置**。面板从右上角弹出，点 × 或按 Esc 关闭。

改完立即保存。已加载的评论不会回溯，刷新页面后新设置才完全生效。

### 屏蔽强度

| 档位 | 规则 |
| --- | --- |
| 小杯 | 账号名含「鱼」或「鲸」，或评论含 `大肥鱼` `肥鱼` `鲸鱼` `本鲸` `本鱼` `主人` |
| **标准**（默认） | 小杯 + 所有 `@` |
| 杀戮 | 标准 + 单字 `鱼` `鲸` + 全角标点 `：` `；` + 破折号 `——` + 直角引号 `「` `」` |
| 只屏蔽 @ | 只看有没有 `@`，昵称和关键词都不参与 |

杀戮档会删掉大量正常评论，连「评论区全是肥鱼」这种吐槽也一起删，还会屏蔽真人发的 `@`。觉得删太多就换回标准。

### 楼中楼

| 档位 | 主楼命中 | 主楼没命中、楼中楼命中 |
| --- | --- | --- |
| **只删楼中楼**（默认） | 整楼删除 | 只删命中的楼中楼，其余保留 |
| 整楼删除 | 整楼删除 | 整楼删除 |
| 不管楼中楼 | 整楼删除 | 楼中楼原样保留 |

「只删楼中楼」会出现空楼：主楼还在，点开回复是空的。想避免就用「整楼删除」。

### 已清记录

打开后，在发评论的输入框和第一条评论之间显示一行 `已清 N 条`。

- 数字含义是「当前这份评论列表里被删掉了多少条」，鼠标悬停能看一级评论和楼中楼各多少条
- 点「展开」列出被删评论：作者、时间、点赞数、命中原因、评论原文；鼠标悬停头像可看用户资料并跳主页
- 往下滚动加载更多，数字跟着变大；切换「最热 / 最新」时归零重算
- 同一页来回滚动、反复展开楼中楼不会重复计数
- 主楼被整楼删掉时，下面的楼中楼按 B站返回的 `rcount` 计数（接口只给前 2~3 条预览，用预览数会少算）
- 记录只留内存里最近 300 条，刷新页面即清空；超出时面板底部会提示「仅显示最近 300 条」

## 几个要点

- **账号名含「鱼」或「鲸」的评论，所有档位一律屏蔽。** 这条最准，大肥鱼账号部署后几乎都会改名成 `xxx的大肥鱼`，正常用户不会这样起名。
- **楼中楼的 `回复 @某某某 :` 是 B站自动拼的前缀，不是用户写的。** 判断 `@` 时会先剥掉它，否则被回复的人名字带鱼，整条回复都会被误删。关键词判定仍然看完整原文。
- **置顶评论始终保留**，包括 UP 主置顶。
- **跟随 B站夜间模式**（`<html class="dark">`），不是跟随系统。

## 相比原版 1.3.0 的改动

原作者目前发布的是 **1.3.0**（759 行），本仓库从它改起，一路迭代到 1.8.0（2114 行）。

一句话概括：**原版只在评论区顶部报一个数，这里把这个数变成了一本能查的账。**

### 已清记录：从一行字变成可查的清单（1.4.0 起）

| | 原版 1.3.0 | 现在 |
| --- | --- | --- |
| 顶部显示 | 一行 `已清 N 条`，鼠标悬停才知道一级 / 楼中楼各多少 | 同样的数字，右侧多一个「展开」按钮 |
| 清单 | 没有 | 可展开，逐条列出被删评论 |
| 每条能看到 | — | 头像、昵称（可点进主页）、IP 属地、等级、绝对时间 + 相对时间、点赞数、命中原因、评论正文 |
| 条数上限 | — | 内存里保留最近 300 条，超出时在底部提示 |

数据是在拦截接口的同一趟里顺手记下的，不额外发请求、不影响评论区加载。

### 楼中楼：能看见里面被删了什么（1.5.0）

原版只把楼中楼按 `rcount` 计入总数，看不到内容。现在「含 N 条回复」变成可点的按钮：先展开接口自带的 2~3 条预览，不够再按每页 20 条往后拉，最多 5 页 100 条；单页失败可以续传，换视频会丢弃在途请求，不会串台。

### 判定：「只屏蔽 @」档不再被昵称带偏（1.5.0）

原版的 `isBlocked()` 先判昵称、再判档位，所以选了「只屏蔽 @」，昵称含「鱼 / 鲸」的账号照样被删 —— 和这一档的字面意思不符。

现在「只屏蔽 @」严格只看正文（剥掉「回复 @xxx：」前缀之后）有没有 `@`，昵称、品牌词、标点都不参与。

同时把 `isBlocked()` 返回 `true / false` 改成 `blockReason()` 返回命中原因（`name` / `brand` / `at` / `char` / `punct` / `dash` / `corner`），清单里才能显示「为什么被删」。

### 空评论区也立刻有反馈（1.5.1）

原版要等真的清掉一条，那行字才出现。现在评论区一加载就显示「已清 0 条」，翻页、换排序、路由切换后都会重新落位，不会因为评论区整块重建就消失。

### 设置面板：档位下面多一行规则说明

原版四个档位只有名字（小杯 / 标准 / 杀戮 / 只屏蔽 @），规则得靠猜。现在每个档位下面有一行小字写清规则，窗口矮时自动压缩面板高度。

### 清单里能直接看用户资料

鼠标悬停在清单条目的头像上会拉取该用户资料卡：头像、昵称、性别、等级、粉丝与获赞数，带「进入主页」按钮。资料拉不到时退回用清单里已有的头像和昵称撑住，不留空框、不显示破图。

### 1.8.0 — 性能

改动的思路是：让每条普通评论在判定阶段尽早出局，让界面刷新不要和页面渲染抢同一帧。

- **品牌词判定加粗筛**：`大肥鱼 / 肥鱼 / 鲸鱼 / 大肥鲸 / 鲸鱼娘 / 本鲸 / 本鱼 / 本肥鱼 / 主人` 九个分支全都含「鱼 / 鲸 / 主 / 本」之一，先用 `indexOf` 扫这 4 个字，命中不了就直接返回，根本不进正则引擎。普通评论最多四次扫描出局。
- **已清记录超出上限时不再整张重画**：旧版每裁掉一条就 `recVer++`，展开中的清单要重画 300 行，每清一条卡一下。现在只从头部 `splice` 多出来的几条、增量删对应节点，并记下累计裁剪数。
- **读接口数据时不动 DOM**：数据回来那会儿操作 DOM 会插队页面渲染，改为标记后交给下一次 `schedulePaint` 统一处理。
- **地址栏参数解析走正则**：只抓 `oid` 和 `type` 两个数字参数，省掉整串 `split('&')` 和逐项 `decodeURIComponent`。
- **夜间模式判断缓存**：读 `className` 会触发强制同步布局，界面刷新路径上一秒要问好几次。改为缓存结果，由 `MutationObserver`（只监听 `class` / `data-theme`）在真正变化时重算。
- **顶部横条按签名更新**：拼一个 `一级数|楼中楼数|展开态|记录数|裁剪态|主题` 的签名字符串，没变就一次 DOM 都不写。

### 版本脉络

`1.4` 折叠清单 → `1.5` 楼中楼展开 + @ 档纠偏 → `1.5.1` 零命中显示 → `1.6` 清单信息补齐（属地 / 等级 / 时间 / 点赞）→ `1.7` 资料卡与交互细节 → `1.8` 性能

### 没有改的部分

四档强度的语义、三种楼中楼策略的语义、接口层拦截（`fetch` / `XHR` 在读取时改写响应）、计数去重规则、跟随 B站夜间模式、置顶评论保留 —— 这些沿用原版设计。

## 不生效时

1. 「允许运行用户脚本」开关开了吗？Chrome / Edge 138+ 必做，大部分问题都在这
2. 打开 B站，按 F12，控制台输入 `window.__dfy`，返回 `1` 说明脚本在跑
3. 域名必须是 `www.bilibili.com`、`t.bilibili.com` 或 `space.bilibili.com`
4. 脚本管理器里确认脚本是启用状态

还是不行的话，去 [Issues](https://github.com/tyis19/dafeiyu-fold/issues) 反馈，附上浏览器版本和 F12 控制台的报错。
